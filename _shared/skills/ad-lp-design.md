# スキル：広告訴求LP設計（セールスレターからの実装）

**使用するエージェント：** campaign-executor（全グループ）／ content-strategist
**入力：** セールスレター訴求文（`_shared/skills/sales-letter.md`の成果物）・広告クリエイティブ（画像/動画）・遷移先URL・CEP
**出力：** LPセクション構成・セクション別コピー・実装指示書（instruction.md形式）・ABテスト設計

---

## このスキルの位置づけ

`sales-letter.md`は「訴求文（コピー）」を作るスキル、`site-design.md`は「SEO集客を目的とした複数ページのサイト構造」を作るスキル。
本スキルはその中間に位置し、**sales-letter.mdで作った訴求文を、広告の受け皿となる単一の高コンバージョンLPに実装する**ためのスキル。
SEO流入ではなく**広告流入（Google/Meta/YouTube/LINE等）専用**の設計思想である点がsite-design.mdと異なる。

```
sales-letter.md（訴求文を作る）→ ad-lp-design.md（LPに実装する）→ media-buyer（広告に入稿する）
```

---

## 前提：広告とLPの「メッセージマッチ」原則

広告のクリック後、**最初の3秒で「自分に関係がある」と思わせられなければ離脱する。** 実際に、動画広告とLPの訴求が噛み合っていなかった工務店の事例では、広告文を「LPへの橋渡し」に書き換えただけでコンバージョン数が10倍になった。

**メッセージマッチの3原則：**
1. **広告文のキーワード・訴求軸を、LPのファーストビュー（ヘッドライン）にそのまま反映する**：広告で「初期費用0円」と訴求したなら、LPの最初の見出しにも同じ言葉を置く
2. **広告のクリエイティブ（画像・動画のトーン）とLPのメインビジュアルのトーンを揃える**：広告で見た世界観と違うLPに飛ぶと「間違えたかな」と離脱される
3. **1つの広告に対して1つのオファー・1つのCTAに絞る**：LPが複数の目的（資料請求もできるし購入もできるし会員登録もできる）を持つと、どの広告からの流入者にとっても最適化されず離脱率が上がる

「新発売」のような、悩みの解決を連想させないワードは広告訴求・LPの一番目立つ位置には向かない。**悩みを解決するパターン**（安さ訴求・比較検討中ユーザー向け訴求・スピード訴求等）のどれに当たるかを`sales-letter.md` STEP2（アプローチパターンの選択）で確定させた上でLP設計に入る。

## STEP 1：セールスレターからLP構成要素へのマッピング

`sales-letter.md`で作成した訴求文の各パーツを、そのままLPセクションに再配置する。**ゼロからコピーを書き直さない**のが本スキルの前提（訴求の一貫性を保つため）。

| sales-letter.mdの生成物 | 対応するLPセクション | 配置目安 |
|---------------------|----------------|--------|
| STEP3 ヘッドライン | メインキャッチコピー（H1） | ファーストビュー |
| STEP4 オープニング | 共感導入文・リード文 | ファーストビュー直下 |
| STEP1 ベネフィット（3〜5個） | ベネフィット訴求セクション（アイコン付き箇条書き等） | 中盤前半 |
| STEP5 ボディコピー中の「信頼性を上げる11の方法」 | 実績・社会的証明セクション（数字・お客様の声・メディア掲載・受賞歴等） | 中盤 |
| STEP5 オファーの構成 | 商品・サービス詳細＋価格・プランセクション | 中盤後半 |
| STEP2 アプローチパターン（ストーリー系の場合） | ストーリーセクション（Before/After・体験談） | 中盤（社会的証明の前後） |
| よくある質問（sales-letter.mdの反論処理に相当する内容） | FAQセクション | 終盤前 |
| STEP6 クロージング | 最終CTAセクション（申込フォーム直前の後押し文） | 終盤 |
| STEP7 P.S. | フッター直前の後押しメッセージ・再訴求 | 最終盤 |

このマッピングを`_shared/skills/consulting-sales-process.md` STEP2（ドラマチックな心理曲線）と組み合わせると、
LP全体が「共感→問題提起→解決策→証拠→安心→行動喚起」という起伏のある構成になる。

## STEP 2：広告とのメッセージマッチ設計

```markdown
## メッセージマッチ確認シート

- 広告で使用した主要キーワード／訴求フレーズ：
- LPファーストビューの見出しに同じ言葉が含まれているか：✅ / ⚠️要修正
- 広告クリエイティブの主な色調・トーン：
- LPメインビジュアルとの一貫性：✅ / ⚠️要修正
- 広告のCTA文言（例：「今すぐ資料請求」）とLPのCTA文言の一致度：
- このLPで達成させたい単一のコンバージョン：
- （複数のCVポイントがある場合）優先順位と、それ以外を目立たせない工夫：
```

**チャネル別の追加考慮事項：**
- **Google検索広告**：検索クエリと完全一致する言葉をファーストビューに含める（検索意図とのマッチ）
- **Meta/Instagram広告**：フィード上のクリエイティブと同じビジュアル要素（色・人物・商品写真）をファーストビューに使う
- **YouTube動画広告**：動画で語った「約束」をLPの最初の一文で回収する（動画の続きを見ている感覚を作る）
- **LINE広告**：LPの最初のセクションはスマホの1画面に完全に収まる情報量にする（LINEユーザーは特に離脱が早い）

## STEP 3：LP標準構成（セクション設計）

広告流入LPは基本的に**縦一直線のワンページ構成**とし、以下の順序を基本形とする。
商材・業界によって増減させるが、**②③④⑤⑦⑨は原則として省略しない**。

```
①ファーストビュー（ヘッドライン＋サブコピー＋ビジュアル＋ファーストCTA）
②共感導入（悩み・課題への共感／オープニング）
③問題の深刻化（このままではどうなるか）
④解決策の提示（商品・サービスの紹介）
⑤ベネフィット（導入後どう変わるか・3〜5個）
⑥仕組み・特長の説明（機能ではなく価値の言葉で。`proposal-writing.md`の機能vs価値の原則を援用）
⑦社会的証明（実績数値・お客様の声・メディア掲載・受賞歴）
⑧商品・サービス詳細（プラン・価格・included内容）
⑨オファー（今だけの特典・保証・返金保証等のリスクリバーサル）
⑩FAQ（反論処理）
⑪最終CTA（クロージングコピー＋申込フォーム）
⑫P.S.・再訴求
⑬フッター（会社情報・特商法表記等の法的必須事項）
```

**CTAは①・⑦の直後・⑪・スクロール追従ボタンの最低4箇所に配置する**（1箇所しかないと機会損失になる）。

## STEP 4：セクション別ワイヤーフレーム設計

```markdown
## セクション設計シート：[セクション名]

- 目的（このセクションで何を達成させるか）：
- 見出しコピー（sales-letter.mdの該当生成物から転記）：
- ビジュアル要素：画像 / 動画 / アイコン / グラフ・数値
- レイアウト：横並び / 縦積み / カード型 / スライダー
- CTAの有無：あり（文言：　） / なし
- モバイル表示時の優先順位（何を残し何を畳むか）：
```

**モバイルファーストの原則：** 広告流入の大半はスマートフォンからのアクセスであるため、PC版を先に作ってスマホ版を縮小するのではなく、
**スマホ1画面に収まる情報量を基準に各セクションを設計してから、PC版でレイアウトを拡張する**。

## STEP 4.5：セクション別ビジュアル素材の生成（画像生成AI活用）

STEP4で各セクションに「画像」が必要と定義した場合、画像生成AI（OpenAI Image 2.0等）を使い、
**ヒアリング→生成のループ**で素材を作成する。コピーライティング（テキスト）と画像生成を分離するのが最大のポイント。

### 画像生成の設計ルール（必須）

```markdown
## 画像生成ルール

1. アスペクト比：スマホ用は縦長「9:16」で統一する（モバイルファーストの原則に合わせる）
2. スタイル：モダン・クリーン・プロフェッショナルなWebデザインスタイルを基本とする
3. 【最重要】画像内に文字（テキスト）を直接描画させない
   → AI生成画像内の日本語テキストは崩れやすく、後から修正もできない
   → 代わりに「キャッチコピー用の広大な余白（negative space）」やダミーのテキストブロック枠を
     配置させ、STEP1でマッピングした実際のコピーは後工程（実装時）にテキストレイヤーとして重ねる
4. 参考画像がある場合、その構図・色使い・雰囲気を生成指示に具体的に組み込む
   （著作権侵害にならないよう、模倣ではなく要素の抽出に留める。`ad-lp-design.md`STEP5の実装前提と同じ注意）
5. セクション間の一貫性：全セクションを通してカラーパレット・ライティングの設定を統一する
   （バラバラのセクションを後から1つのLPとして繋げると違和感が出るため）
```

### ヒアリング→生成の対話フロー

```
STEP a：全体方針のヒアリング（LP全体で1回のみ）
  1. 商品・サービス名と内容
  2. ターゲット読者（ペルソナ）
  3. 希望する全体の雰囲気（トンマナ）
  4. メインカラー・サブカラー
  5. 全体像の参考画像（任意）

STEP b：セクション構成の確認
  STEP3の13セクション構成をベースに、画像が必要なセクションのみ制作順序を確定する

STEP c：セクションごとの詳細ヒアリング＋生成（必要なセクション数だけループ）
  1. そのセクションの目的（STEP4のセクション設計シートと同じ）
  2. 具体的なビジュアルイメージと要素
  3. 文字を入れるスペースの希望（例：上部にキャッチコピー用の余白、下部に商品画像）
  4. このセクション専用の参考画像の有無（任意）
  → ヒアリング内容をもとに画像を生成し、次のセクションへ進む
```

**運用上の注意：** 生成に使った詳細プロンプト（英語指示文等）は成果物には含めず、**生成された画像そのものをアウトプットとして扱う**。
STEP5の実装指示書（instruction.md）には、生成した画像のファイルパスと、その上に重ねるコピー（STEP1のマッピング結果）を指定する。

## STEP 5：Claude Code等での実装指示書（instruction.md）の作成

LPをコーディングエージェントに実装させる場合、以下の手順・構成で指示することで実装精度が上がる。

### 実装前のインプット収集

```markdown
## 実装前インプットチェックリスト

- [ ] LPの勝ちパターンに関する参考記事を読み込ませ、構成の妥当性を確認する
- [ ] 競合・同業種のLPを分析させ、差別化ポイントを反映する
- [ ] 参考にしたいデザイントンマナのLP・デザインカンプ（Figma等）を用意する
      ※参考にする場合は著作権侵害に当たらないよう、模倣ではなく要素の抽出に留める
- [ ] 自社の過去コンテンツ（ブログ・note等）を読み込ませ、文体（トンマナ）を再現させる
      → 文体が抽出されている既存コンテンツがあるほど再現精度が上がる
```

### instruction.mdの構成

```markdown
## instruction.md 構成テンプレート

1. 全体構成（STEP3の13セクション構成をそのまま記載）
2. 技術スタック・命名規則（HTML/CSS/JS or 使用フレームワーク）
3. デザイントンマナ（色・フォント・余白のルール）
4. セクションごとの詳細指示（②以降、1セクション1見出しで分割記載）
   - コピー本文（STEP1のマッピング結果をそのまま転記）
   - ビジュアル要素の指示
   - CTA文言
```

**分割の原則：** 「LP全体を一気に作って」と一度に投げると、コンテキスト長超過による自動要約（auto-compaction）で
指示の精度が落ち、意図しないレイアウトになりやすい。**セクション単位で指示を分割し、1回のやり取りで扱う情報量を絞る**ことで精度が上がる。
ただしファイルを分けすぎるとトークン効率が落ちるため、13セクションを2〜4ブロック程度にまとめるのが目安。

### 実装フロー

```
STEP A：instruction.mdに全体構成・技術スタック・命名規則を記述する
STEP B：Plan Mode（計画を立ててから実装するモード）で方針をすり合わせる
        → いきなり実装させると、言語化が甘い部分をAI側の解釈で補完してしまい「そうじゃない」が頻発する
STEP C：Planに基づき、セクション単位で実装を進める
STEP D：デザインカンプ（Figma等）がある場合はMCP連携で該当セクションのデータのみを渡す
        → ファイル全体を読み込ませると情報過多で崩れやすいため、セレクションベースで渡すのが望ましい
STEP E：実装を確認し、1箇所ずつ具体的な修正指示を出す（「なんかもっとこう」等の曖昧な指示は精度を下げる）
STEP F：レスポンシブ（モバイル表示）を必ず確認する
```

## STEP 6：ABテスト設計への接続

LP公開後は`_shared/skills/abtest-design.md`を参照し、特に以下の要素を優先的にテストする。

```markdown
## LPのABテスト優先順位

1. ファーストビューのヘッドライン（メッセージマッチの精度が最もCVRに影響する）
2. ファーストビューのCTA文言
3. 社会的証明の見せ方（数値訴求 vs お客様の声訴求）
4. オファーの提示順（価格を先に見せる vs 価値を先に見せる）
5. FAQの有無・内容
```
