# スキル：営業担当者タイプ分類・アサイン最適化・結果分析

**使用するエージェント：** abm-strategist（アサイン判断）／ sales-enablement-executor（スクリプトのタイプ別調整）／ customer-success-analyzer（結果分析）
**入力：** 営業担当者プロファイル・ステークホルダーマップ（`stakeholder-analysis.md`のDiSC分析結果）・商談履歴
**出力：** 営業タイプ定義シート・アサイン推奨・相性マトリクス・結果分析レポート

---

## このスキルの位置づけ

`stakeholder-analysis.md`のDiSC分析は「**顧客側**の性格タイプ」を分類するスキルだった。
本スキルはこれと対称的に「**営業担当者側**の性格タイプ」を分類し、両者の相性・スクリプトとの相性・
最適なアサイン・そして実際の結果（勝率）から学習するループまでを扱う。

```
顧客のDiSC（stakeholder-analysis.md） × 営業担当者のDiSC（本スキル） × スクリプトスタイル（sales-script.md）
    ↓
最適なアサイン（本スキル STEP3）
    ↓
商談実施（sales-enablement-executor.mdが生成した素材で）
    ↓
結果分析（本スキル STEP4）→ 勝率パターンを学習 → knowledge-curator-crmへ蓄積 → アサインルールを継続改善
```

**重要な前提：** タイプ分類は「決めつけ」ではなく「傾向の把握」。実際の商談では個人差が大きいため、
本スキルはアサインの**初期仮説**として使い、結果分析（STEP4）で継続的に検証・修正する。

---

## STEP 1：営業担当者のタイプ分類

顧客と同じDiSC 4分類（`_shared/skills/stakeholder-analysis.md`参照）を営業担当者にも適用する。
加えて、営業特有の2軸（狩猟/耕作・経験レベル）を組み合わせて多面的にプロファイリングする。

### 1-1. DiSCスタイル（顧客分析と共通の枠組み）

| スタイル | 営業としての強み | 営業としての弱み |
|---------|--------------|--------------|
| **D（Dominance）** | 決断が早い・結論から話せる・プレッシャーに強い・クロージング力が高い | 相手のペースを無視しがち・傾聴不足・強引に見えるリスク |
| **i（influence）** | 関係構築が早い・場の空気を作れる・ストーリーテリングが得意 | 詰めが甘い・データの裏付けが弱い・脱線しやすい |
| **C（Conscientiousness）** | 論理的で正確・データ・資料の質が高い・信頼されやすい | スピード感に欠ける・雑談を避けがち・決断を急がせるのが苦手 |
| **S（Steadiness）** | 傾聴力が高い・信頼関係の構築が丁寧・長期的関係に強い | クロージングを先延ばしにしがち・主導権を握るのが苦手 |

### 1-2. 狩猟型（ハンター）／耕作型（ファーマー）

| タイプ | 特徴 | 向いているフェーズ |
|-------|------|--------------|
| **ハンター型** | 新規開拓・スピード重視・成果に対する競争意欲が強い | 認知・リード獲得（TOFU）・新規商談の初期接触 |
| **ファーマー型** | 既存関係の深耕・丁寧な合意形成・長期的信頼構築 | 育成・商談化（MOFU）・カスタマーサクセス・アップセル |

### 1-3. 経験レベル・専門性

```markdown
## 営業担当者プロファイルシート

- 氏名：
- DiSCスタイル：D / i / C / S（複合の場合は主/副で記載。例：D/i）
- ハンター/ファーマー傾向：
- 業界経験・専門性：
- 過去の得意な商材タイプ：即決型 / 提案型（`consulting-sales-process.md`の分類に対応）
- 過去の勝率実績（あれば）：
- 得意なファネル段階：TOFU / MOFU / BOFU / アフター
```

## STEP 2：営業タイプ×顧客タイプの相性マトリクス

`stakeholder-analysis.md`で特定した商談相手（特に決裁者・推進者）のDiSCスタイルと、
営業担当者のDiSCスタイルを掛け合わせ、相性と調整ポイントを確認する。

| 営業＼顧客 | D顧客 | i顧客 | S顧客 | C顧客 |
|---------|------|------|------|------|
| **D営業** | △ 主導権の衝突リスク。役割を分け結論を先に譲る配慮を | ◎ スピード感が合う。iの社交性とDの決断力が噛み合う | △ 強引に見えやすい。ペースを落とし傾聴を意識 | △ 直感的な進め方とCの慎重さが衝突。データ提示必須 |
| **i営業** | △ 脱線がストレスに。端的に・結論から話す訓練が必要 | ◎ 大いに盛り上がるが詰めが甘くなりがち。クロージングは意識的に | ◎ 感情面で共鳴しやすい。ただし決断を急がせる工夫を | △ ノリが軽く見られるリスク。データ・根拠を必ず添える |
| **S営業** | △ 受け身な姿勢が物足りなく映る。明確な提案を用意する | ◎ 良好な関係を築きやすい。ただし押し切られないよう主導権を意識 | ◎ 心地よい関係だが決断が先延ばしに。締切設定が必須 | ◎ 双方が慎重なため信頼構築しやすい |
| **C営業** | △ スピード不足に映る。結論を先に言う訓練を | △ データ偏重で退屈させるリスク。ストーリーを混ぜる | ◎ 相性が良い。ただし押しが弱くなりがちなので後押しを意識 | ◎ データオタク同士で信頼構築は早いが、決断が遅くなりがち |

**判定基準：** ◎＝相性良好（そのまま進めてよい）／△＝相性注意（右列の調整ポイントを商談前にスクリプトへ反映する）

## STEP 3：営業タイプ×スクリプトスタイルの相性

`sales-script.md`の4つの物語・6つの認知バイアスは、営業担当者のDiSCスタイルによって「自然に得意なもの」が異なる。
台本を画一化せず、**担当者の強みを生かす型**でスクリプトをカスタマイズする。

| 営業スタイル | 得意な物語（`sales-script.md` STEP4） | 得意な認知バイアス活用（STEP6の6分類） | スクリプト生成時の調整方針 |
|---------|--------------------------------|------------------------------|------------------------|
| **D営業** | 物語④：製品と解決策の物語（結論・解決策を先に） | プロスペクト理論（損失回避）・アンカリング | 結論ファーストの構成にする。感情パートは短縮し、数値インパクトを前面に |
| **i営業** | 物語①：個人的な物語（共感を生む自己開示） | バンドワゴン効果・利用可能性ヒューリスティック | ストーリー・エピソードのパートを厚くする。データパートは要点のみに絞る |
| **S営業** | 物語②：見込み客の物語（相手への深い共感） | 選択支持バイアス（過去の選択の肯定） | 傾聴・共感のパートを厚くする。クロージングのセリフを台本に明示的に組み込む（先延ばし防止） |
| **C営業** | 物語③：問題の物語（データに基づく問題の深刻化） | 確証バイアス（信念と一致するデータの提示） | データ・事例のパートを厚くする。ストーリーパートは簡潔にし、根拠を積み増す |

**sales-enablement-executor.mdへの指示：** 商談スクリプトを生成する際、担当する営業担当者のDiSCスタイルを
入力パラメータに加え、上記の調整方針に沿って**同じ商談でも担当者ごとに異なる型のスクリプト**を生成する。
「みんな同じ台本」を避け、話者が自然に話せる構成にすることで再現性と成約率が上がる。

## STEP 4：メンバーアサイン定義

### アサインの優先順位ルール

```markdown
## アサイン判断フロー

STEP A：商談相手（決裁者・推進者）のDiSCスタイルを確認する
  → stakeholder-analysis.mdの分析結果を参照

STEP B：STEP2の相性マトリクスで「◎」評価の営業担当者を優先候補とする
  → 複数該当する場合はSTEP Cへ

STEP C：商材タイプ・ファネル段階で絞り込む
  → 即決型商材・TOFU段階 → ハンター型を優先
  → 提案型商材・MOFU以降 → ファーマー型を優先
  → 高単価・技術的説明が必要 → C型営業の専門性を優先

STEP D：業界経験・過去の類似案件の勝率実績で最終判断する
  → 同業界での成約実績がある担当者を優先

STEP E：候補者不在の場合の代替ルール
  → 完全な「◎」相性がいない場合、△評価の担当者を割り当て、
    STEP3の調整方針を必ずスクリプトに反映させることを条件にアサインする
  → 新人・経験の浅い担当者をアサインする場合は、ベテランのオブザーブ同席を検討する
```

### アサイン推奨シート

```markdown
## アサイン推奨：[アカウント名]

- 商談相手の主要DiSCスタイル：（決裁者：　／推進者：　）
- 商材タイプ：即決型 / 提案型
- 現在のファネル段階：TOFU / MOFU / BOFU / アフター

### 候補者評価
| 営業担当者 | DiSCスタイル | 相性評価 | ハンター/ファーマー適合 | 業界経験 | 総合推奨度 |
|---------|-----------|-------|-----------------|--------|---------|

### 推奨アサイン
- 第1候補：
- 推奨理由：
- スクリプト調整方針（STEP3参照）：
- 代替候補（第1候補が不在の場合）：
```

## STEP 5：セールス結果分析の定義

商談結果を「営業タイプ×顧客タイプ×スクリプトスタイル」の組み合わせで記録・分析し、
**どの組み合わせが実際に勝率が高いのか**をデータで検証する。STEP2・3の相性マトリクスは仮説であり、
この分析結果によって継続的に更新する。

### 5-1. 記録すべきデータ項目

```markdown
## 商談結果記録シート（Twenty CRM Opportunityに記録）

- アカウント名：
- 担当営業のDiSCスタイル：
- 商談相手（決裁者/推進者）のDiSCスタイル：
- 相性マトリクス上の事前評価：◎ / △
- 使用したスクリプトスタイル（STEP3のどの型か）：
- 商材タイプ：即決型 / 提案型
- ファネル段階：
- 結果：成約 / 失注 / 保留
- （失注の場合）失注理由：
- 商談サイクル長（初回接触〜結果確定までの日数）：
```

### 5-2. 分析の切り口

```markdown
## 勝率マトリクス分析

### 切り口1：営業タイプ×顧客タイプ別の勝率
| 営業＼顧客 | D顧客 | i顧客 | S顧客 | C顧客 |
|---------|------|------|------|------|
| D営業 | 勝率%（n件） | | | |
| i営業 | | | | |
| S営業 | | | | |
| C営業 | | | | |

→ STEP2のマトリクス（仮説）と実際の勝率を比較し、乖離があれば仮説を更新する

### 切り口2：スクリプトスタイル別の勝率（担当者スタイル別）
| 営業スタイル | 型通りのスクリプト使用時の勝率 | 型を無視したスクリプト使用時の勝率 |
|---------|---------------------------|---------------------------|

→ STEP3の「担当者の強みを生かす型」が実際に効果があるかを検証する

### 切り口3：商材タイプ×ハンター/ファーマー別の勝率
| | 即決型商材 | 提案型商材 |
|--|---------|---------|
| ハンター型 | | |
| ファーマー型 | | |

### 切り口4：商談サイクル長の分析
- 相性◎の組み合わせと△の組み合わせで、商談サイクル長に差があるか
- △の組み合わせでSTEP3の調整方針を実施した場合としなかった場合の比較
```

### 5-3. 学習ループへの接続

```
商談結果の記録（5-1）
    ↓
一定件数（目安：各セル10件以上）蓄積後に勝率マトリクスを更新（5-2）
    ↓
STEP2・STEP3の仮説マトリクスと実績に乖離があれば
  → customer-success-analyzerが乖離を報告
  → abm-strategistがSTEP4のアサイン優先順位ルールを修正
    ↓
確定した勝率パターン（統計的に有意な差が出たもの）は
  knowledge-curator-crm（Twenty CRM）のPlaybookLearningに「営業×顧客タイプの確定知識」として記録する
```

**注意：** サンプル数が少ない段階（各セル10件未満）では、実績値を鵜呑みにせず、
STEP2・3の理論的な相性マトリクスを引き続き参考にする。
