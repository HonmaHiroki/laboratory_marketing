## PART 1：事前期待探索

顧客満足は事前期待と実績評価の相対関係で決まる（`loyalty-research.md`参照）。したがって**どの事前期待を的に据えるかで、サービスの姿と価値がガラリと変わる**。

### 事前期待の4分類

| 種類 | 定義 | 施策上の意味 |
|-----|------|-----------|
| **共通的な事前期待** | すべての顧客が共通して持つ期待（例：清潔な部屋） | 応えても「当たり前」。これだけでは選ばれ続けない |
| **個別的な事前期待** | 顧客ごとに異なる期待（例：枕の好み） | 組織で共有し「事前期待のバトンパス」をすることで対応力が上がる |
| **状況で変化する事前期待** | 同じ顧客でも状況（天候・体調・急ぎ・予算）で変わる期待 | 顧客DBを見ても意味がない。**事前期待へのアンテナ感度**の育成が必要 |
| **潜在的な事前期待** | 思ってもみないサービスで感動する元になる期待 | 成功事例を「どの事前期待に応えたから成功したか」で紐解いて共有する |

**注意**：顧客DBに「プロフィール」「利用履歴」はあっても、肝心の「**事前期待**」の情報がないケースが多い。担当変更が顧客との縁の切れ目にならないよう、事前期待こそ組織で共有する。

### 事前期待の基本構造（階層性）

事前期待は階層構造をしており、表面的な期待の理由を辿ると深い階層の期待が見つかる。深層には「価値観や人生観に触れる事前期待」「諦めている事前期待」がある。

- **深い階層の事前期待から、いくつもの表面的な事前期待が派生している**
- したがって、様々な表層的期待に応えようとするより、**深層の事前期待を捉えて応える方が波及効果が大きい**
- ただし「幸せになりたい」レベルまで深堀りするとサービスとして応えようがない。**自分たちの事業がどの階層に着眼すべきかを議論する**

### 事前期待の的を絞る「4つのWHY」

```markdown
## 4つのWHYチェック

□ 顧客のWHY
  この事前期待に応えることで、なぜ顧客に選ばれ続けることができるのか

□ 競合のWHY
  この事前期待に応えることで、なぜ競合に対して競争優位を築き続けられるのか
  ※競合がどこかは自社の認識だけで決めない。顧客の事前期待から見て自社がどこと比較されているかを理解する

□ 自社のWHY
  なぜ自社が、この事前期待に応えるべきだと言えるのか
  ※理念・ビジョン・戦略・ブランディングと紐づく。「自分たちらしさ」を事前期待で再定義する作業でもある

□ 自分自身のWHY
  活動メンバー各自が、いち個人としてなぜこの事前期待に応えたいと思っているのか
  ※メンバー自身の本気の思いがなければ、キレイな絵を描いても誰の心も動かせない
```

### 狙い目となる事前期待の2類型

**① 諦めている事前期待**
顧客が「ここまでは期待しすぎだよね」と諦めてしまっている期待。これに応えるサービスは圧倒的な差別化になる。
→ 例：「シニアマーケット」を「**何を諦めている事前期待のマーケットなのか**」で再定義すると、打ち出すべきサービスが明確になる。

**② よくある潜在的な事前期待（身近な成功事例）**
顧客にとっては潜在的でも、プロであるサービス提供者にとっては想定内の期待。ベテランや感度の良いスタッフが経験知として捉えている。**社内の成功事例を事前期待の観点で分析すると見つかる**。

### 事前期待マネジメント

事前期待は「捉えて応える」だけでなく「マネジメントする」対象。

- **なぜ必要か**：営業が大風呂敷を広げると事前期待が過剰に膨らみ、どんなに頑張っても満足されない。また付き合いが長くなると、良いサービスほど事前期待が膨らみ「以前はよかったのに」と言われる（サービスレベル向上と膨らむ期待のイタチごっこ）
- **王道＝妥当水準への引き戻し**：テーマパークの待ち時間表示、受注が見えたら広げた風呂敷を上手にたたむ営業、など
- **その他の方向**：立ち上げ期は「過小な事前期待を膨らませる」、一人勝ちを狙って「どんどん膨らませる」、応えられないことは「そっとしておく」

### 価値共創と「適応」の違い

| | 定義 | 事前期待の扱い |
|--|------|------------|
| **適応** | 顧客の要望やニーズに応える | 事前期待は進化しない。同じ期待に延々と応えるだけ |
| **価値共創** | 顧客との協働を通して事前期待を進化させる | 事前期待の創出・喚起・成長・強化が起きる |

> **"価値を創造する"とは、"事前期待を創造する"ということ。**

## PART 2：サービスプロフィットチェーン（SPC）設計

### SPCの7ステップ

```
1. 従業員へのサービス品質（内部品質）が従業員満足度を高める
   → 「従業員も顧客である」という意識で内部品質を改善する
2. 従業員満足が従業員ロイヤルティを高める
3. 従業員ロイヤルティが生産性・貢献度を高める
4. 生産性向上が顧客へのサービス品質を高める
   → 最初から正しいサービスを提供することに加え、ミス発生時のリカバリー力と現場の裁量が重要
5. サービス品質が顧客満足を高める
6. 顧客満足が顧客ロイヤルティを育み、収益性と成長を促進する
7. 収益と成長が従業員に還元される（報酬・福利厚生への再投資）→ 1へ
```

日本のホテルを対象とした6年間の追跡調査でも、従業員満足度→サービス品質→顧客満足度→稼働可能客室あたり粗利益の関係が実証されている。

### 4つの観点におけるSPC設計

**① 従業員満足度向上**
- コアバリュー（価値観・行動指針）を浸透させる → 現場が判断に迷わず素早く適切な判断ができる
- 従業員から聴く仕組みを作る（ES調査・1on1・業務改善提案の受け皿）
- キャリアの幅を広げる（上下関係ではなくフラットな横の異動を可能に）
- 褒めあう・感謝を伝える仕組み（サンクスカード・ピアボーナス）

**② サービス品質向上**
- 顧客の声を聞く仕組み（CS調査・NPS・レビュー/SNS・現場担当者のフィードバック）
- **ホールプロダクト**を基準にした段階的改善：コアプロダクト → 期待プロダクト → 拡張プロダクト → 理想プロダクト
- 業務プロセスの最適化（マニュアル整備・属人化の排除・ボトルネックの可視化・ツール導入による自動化）

**③ 顧客満足度向上**
- CX強化（MOT＝モーメント・オブ・トゥルースで常にポジティブな印象を／CRM・CDP活用のパーソナライズ）
- フィードバックの活用（NPS・CSATの定期実施、VOCプログラムの導入）
- ※主観的な推測（「顧客はきっとこう感じている」）で施策を進めると的外れになる

**④ 顧客ロイヤリティ向上**
- リピーター戦略（契約継続年数に応じた優遇・導入事例の共同制作・ウェビナー登壇などの共創機会）
- 口コミ・紹介の促進（紹介制度・UGC支援・アンバサダープログラム）

### SPCデータ収集と検証

```markdown
## 収集すべきデータ

### 従業員満足度（ES）
- サーベイ設計：1〜5または1〜7のリッカート尺度。設問ごとの平均スコアと好意的回答比率（4〜5の%）
- 項目カテゴリ：基本属性／仕事・役割・成長／報酬・福利厚生／上司・マネジメント／
  職場環境・人間関係・風土／会社への信頼・エンゲージメント（社内版NPSを含む）
- 集計単位：チーム・部署・店舗・拠点・マネージャー単位（顧客指標と紐づけやすいレベル）
- 集計値：平均ESスコア／好意的回答比率／回答率／スコアの分散

### 従業員定着率
- 必要項目：従業員ID・入社日・退職日・雇用区分・部署ID・上司ID・勤務地
- 計算：期間開始時に在籍していた従業員のうち、期間終了時まで在籍している割合
- ※「自発的離職のみ」か「全離職」かを事前に定義する

### 従業員生産性
- 一人当たり売上高／一人当たり粗利・付加価値／人時生産性（売上または粗利 ÷ 総労働時間）
- 業務別：処理件数・一次解決件数（CS）／受注件数・受注金額（営業）

### 顧客満足度
- CS（5〜7段階）／NPS（0〜10）／CSI・JCSI（複数要素の加重平均）
- トランザクション後アンケート＋定期CS調査

### 収益性
- 営業利益率／粗利率／顧客収益性／従業員あたり利益
- 間接費は売上比・取引件数比・人件費比などで配賦
```

```markdown
## チェーン検証の手法

### 従業員満足度 → 従業員定着率／生産性
- 相関分析：ES度合いと定着率・生産性の相関を検証
- t検定：ESを閾値でグループ分けし、ESが高いグループほど定着率・生産性が高いかを検証

### 従業員定着率/生産性 → サービス品質
- サービス運用KPI（応対時間・一次解決率・エラー率・クレーム数・SLA達成率）との相関分析・t検定

### サービス品質 → 顧客満足・ロイヤリティ
- 重回帰分析：目的変数にCSAT/NPS、説明変数にサービス品質指標を置き、**どの指標が最も寄与するか**を検証
- 相関分析・t検定

### 顧客ロイヤリティ → 収益性
- 相関分析：CES・NPSと売上・利益の相関
- t検定：ロイヤリティ指標でグループ分けし、収益性の有意差を検証
```

## PART 3：サービスプロセスのモデル化

現場の経験やセンスで磨かれた知恵・工夫は個人の頭の中にあり組織で活用できていない。これを見える形にして**現場の経験知を組織の力に変える**のがサービスプロセスモデルの役割。

### モデル化の5ステップ

**STEP 1：サービスプロセス定義**
「サービス提供プロセス」と「**顧客プロセス**」を必ずセットで定義する。多くの場合、顧客プロセスが定義されていない。両方を並べると、顧客にとって重要なプロセスの欠落や、順番の不親切さが見つかる。

サービス提供プロセスの標準的な区分（toB/SaaS型）：
| プロセス | 設計すべきこと | 主な測定指標 |
|--------|------------|-----------|
| **導入（オンボーディング）** | 段階的ステップ設計・顧客ごとのゴール設定・支援体制（ハイタッチ/ロータッチ/テックタッチ）・コンテンツ整備 | オンボーディング完了率・初回利用までの期間・アクティベーション率・TTV |
| **問題解決（サポート）** | マルチチャネル対応・セルフサービス充実・FAQ/ナレッジベース・チャットボット・対応履歴共有 | 初回応答時間・解決時間・CSAT・自己解決率 |
| **適応（アダプション）** | 活用状況モニタリング・活用提案・継続的な教育・定期タッチポイント・ユーザーコミュニティ | DAU/MAU・機能利用率・エンゲージメントスコア・ヘルススコア |
| **契約継続（リニューアル）** | 定期パフォーマンスレビュー・更新3〜6か月前からのアプローチ・成功体験の可視化・解約リスク予兆検知 | 更新率・チャーンレート・NRR |
| **契約拡大（アップセル/クロスセル）** | ニーズ変化の把握・提案タイミング設計・プラン設計・データドリブンな提案 | アップセル率・クロスセル率・拡張ARR・ARPU |
| **愛着・口コミ（ロイヤリティ/アドボカシー）** | 会員/ランク制度・限定特典・リファラル制度・コミュニティ育成・成功事例のコンテンツ化 | NPS・LTV・リファラル数・コミュニティ参加率 |

**STEP 2：事前期待定義**
プロセスごとに事前期待を定義する。**共通的な事前期待だけを設定すると「当たり前サービス」にしかならない**。個別的・状況変化・潜在的な事前期待を意識して組み立て直す。

**STEP 3：サービス品質定義**
プロセスごとに「注力すべきサービス品質」を6要素（正確性・迅速性・柔軟性・共感性・安心感・好印象）で定義する。これにより努力ポイントが明確になり、業務の優先順位付けと取捨選択が可能になる（＝サービス向上と効率化の両立）。

**STEP 4：勝負プロセス定義**
全プロセスを全力で頑張ることはできない。**どのプロセスでどんなアクションが価値向上のカギを握るか**を明確にする。裏を返せば、勝負プロセス以外は効率化して負荷を減らすべきポイント。

- **成果分岐点をモデルにドッキング**：リピート・紹介には「感情的な大満足」のみが結びつく（`loyalty-research.md`参照）。この事業成果に直結するポイントをプロセスモデルに組み込む
- **本当の勝負プロセスは意外なところにある**：例）提案営業の勝負プロセスは「提案」ではなく「**相談**」。優秀な営業は提案プロセスを重視せず、その前の相談プロセスで心を掴んでいる
- **チャンスロスプロセスを探す**：提案の打率が低い営業は提案数を追い、忙しさで相談に乗る余裕を失い、さらにチャンスロスが重なる負のスパイラルに陥る。**「顧客の事前期待に応えるチャンス」「顧客に価値ある事前期待を持ってもらうチャンス」をロスしたポイント**を探す（※「売り付け」「囲い込み」のチャンスではない）

**STEP 5：作動スイッチの組み込み**
モデルを設計してもメカニズムが駆動しなければ価値は届かない。**勝負プロセスの前段階で、そのプロセスが起動するための工夫**を組み込む。

- 例）勝負プロセスが「相談」なら、初回訪問で一方的に会社説明や仮提案をするのではなく、顧客の背景・問題意識を聞き、思いに共感し、構想に意気投合する。「**何を提案するか」ではなく「どんな思いを共有できるか**」が作動スイッチになる
- 見つけ方：事前期待から逆算する。勝負を決めるために、どのプロセスでどんな事前期待を持っていてもらうべきかを紐づける

### ESポイントの組み込み

CSとESを別物扱いせず、同時に高めるのがサービスモデルの役割。

- **「スキ」を磨くサービスプロセス設計**：「自分のスキルを活かした仕事が顧客の役に立った」とやりがいを実感するポイントをプロセスに組み込む（例：新人に必ず会計後のお見送りポジションを与え、「ありがとう」「また来るね」と言われる経験を積ませる外食企業）
- **「やってみる」を後押しするマネジメント**：イキイキしているから「やってみる」のではなく、「やってみる」からイキイキする。**「スキル」を磨くことに「スキ」を磨くことを掛け合わせる**

### 顧客と従業員の事前期待マトリクス

横軸に「顧客の事前期待にマッチしているか」、縦軸に「従業員の事前期待にマッチしているか」を置くと、仕事は4分類できる。

| タイプ | 顧客の期待 | 従業員の期待 | 意味 |
|-------|--------|----------|------|
| **A** | ○ | ○ | **好きな仕事・得意な仕事**。成功体験→モチベーション→さらに応える行動、の好循環 |
| **B** | ○ | × | **自己犠牲な仕事**。顧客は喜ぶが現場は疲弊。従業員が去り事業も衰退 |
| **C** | × | ○ | **自己都合な仕事**。従業員・事業の都合を顧客に押し付けている |
| **D** | × | × | **やらされ仕事**。仕組み化・自動化（DX）の対象 |

→ **Aのクロスポイントを作り、広げていく**ことがサービスモデル設計の目標。

### 価値共創サービスモデルのチェックリスト（T1〜T7）

```markdown
## 顧客接点：価値共創サイクル
□ T1 価値提案：どの事前期待に向けて価値を提案するのかが明確になっているか
□ T2 利用価値共創：顧客と一緒に価値を生み出すプロセスが設計できているか（個人のセンス頼みでないか）
□ T3 満足評価からの事前期待形成：顧客が次の事前期待を形成するための働きかけができているか

## 事業組織内：サービス進化サイクル
□ T4 価値発信把握：顧客評価やVOCに優先度を付けて分析・活用できているか
  ※すべてに闇雲に対応するとサービスが同質化する。どの事前期待の顧客からのフィードバックかを把握する
□ T5・T6 提供価値共創：顧客接点で得た気付きでサービス設計を進化させる取り組みができているか
  ※現場の暗黙知を組織の形式知にする

## 企業経営：事業成長サイクル
□ T7 付加価値共創：両サイクルを回し続けるための意思決定・投資ができているか
  ※目先の売上・利益優先ではなく、成果の手前のメカニズムに投資する
```

## PART 4：サービス改革の推進

### 乗り越えるべき6つの壁

| 壁 | 症状 |
|---|------|
| **顧客不在の壁** | 良いサービスを作っても喜ばれない。事前期待を捉えず打ち手を探している |
| **建前の壁** | 「サービス＝おまけ」意識が残り、本業と別物扱い。改革がキレイゴトと白けられる |
| **闇雲の壁** | 何から手をつけるか分からず、スローガンを掲げて現場に丸投げ |
| **実行の壁** | 格好の良いモデルを描いても現場が体現できず絵に描いた餅になる |
| **継続の壁** | 立ち上げ時は盛り上がるが忙しさに負けて長続きしない |
| **情熱の壁** | 壁にぶつかるたびに諦める理由を並べてしまう |

### 4つのイノベーション力

1. **サービスモデルを築き上げる力**：モデル化により価値の再現性が高まり、他事業への展開も容易になる
2. **「まぐれ当たり」を見つける力**：イノベーションのきっかけは「おやっ」「もやっ」という違和感。**事前期待の的が、まぐれ当たりへの感度を高める**
3. **確信に変える力**：まぐれ当たりを自分たちで再現できるよう努力する。**「実験室」として実践型で取り組み、サービスモデルを仮説として検証・軌道修正する**
4. **壁に向かう力**：「ビジョン・危機感・使命感」の3点セットに火を付ける

### 改革の4段階「4UP STEP」（6つの壁を4回越える）

```
① WAKE UP（スモールスタート）
   コアメンバー自身の中にある6つの壁を乗り越える。
   事前期待の的を見定め、サービスをモデル化し、シナリオを描き、自ら実践してブラッシュアップ。
   → 議論が「どうやって周囲に展開するか」に移り始めたら次へ

② TIE UP（実践拡大）
   10人誘って乗ってくる2〜3人の仲間とタッグを組み、前向きに実践して成果を示す。
   → 仲間が増え「事業や組織全体をどう変えるか」の議論が始まったら次へ

③ SCALE UP（全体展開）
   カギは**ミドルマネジメント**。経営と現場が本気でも組織の要が動かなければ波及しない。
   前向きなミドルマネジメントの組織で徹底的に実践し、目標達成につながる成果を出す。
   → 他のミドルマネジメントが「役に立つ」と実感して関わってくれるようになる

④ BUILD UP（しくみ化）
   誰かの旗振りに頼らず定着させる。
   ここまでのアウトプット（シナリオ・サービス設計・実践ガイド・育成プログラム・評価指標）を活かせばよく、
   新たに作る必要はない。既に実践され成果実感まで得られているため、変化への抵抗を乗り越えられる
```

### 改革で意識すべき「自己犠牲からの脱却」

サービス事業の構成要素（顧客・従業員・事業）の**どれも犠牲にしない**ことが原則。以下は典型的な失敗パターン。

- 「顧客拡大」が顧客を犠牲にする（売りつけ・囲い込み視点）
- 自己犠牲を前提にした「サービス向上」「おもてなし」（提供側が疲弊）
- 「働き方改革」が働きがいを犠牲にする（残業規制で働き盛りのモチベーション低下）
- 「生産性向上」でサービスの価値まで削ぎ落とす（顧客接点の安易な省力化）
- サービス設計なしの「技術革新」（AI/RPA導入で顧客ががっかり）
- 「製造業のサービス化」でサービスをおまけ扱いする
- 地域社会がげんなりする「地域密着サービス」（地域資源を集客のネタにして顧客を独り占め）
  → 地域密着型は**その事業が地域の誇りになり、地域から応援される**ことが本来の姿

### サービス人材育成の方向性

**失点撲滅型 → 得点評価型へのステージアップ**が必要。失点撲滅型マネジメント（クレーム・ミスへの徹底指導、失点しない社員を評価）では、サービスマインドの発揮が「報われない努力」になり、現場が疲弊する。

**ハイパフォーマー育成の要点**：
ハイパフォーマーは「サービスの**プロセス**に対する評価」が抜群に高い。しかし従来の育成は「成果」の評価（業務研修・専門技能研修）に偏っている。

さらに、ハイパフォーマーから学ぼうとすると「**何をやっているのか（打ち手）**」ばかりに着目しがちだが、打ち手は他のスタッフと大差ない。差は「**顧客の事前期待へのアンテナ**」にある。ハイパフォーマーは「顧客が特に何を期待しているか」への感度が高く、それに合わせて打ち手を変えている。

→ 育成では、**打ち手を磨くこと以上に「事前期待へのアンテナ」の方向を明らかにし、感度を高める**。「どんな事前期待への感度を高め、その期待にどう応えることに価値があるのか」をサービス設計として見える形に定義する。
