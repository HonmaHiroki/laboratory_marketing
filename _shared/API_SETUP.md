# API事前準備ガイド（market-scout用）

market-scoutが使用する全API・データソースについて、実際にデータ取得を始める前に必要な準備手順をまとめる。
**このドキュメントは`_shared/agents/market-scout.md`から参照される。API自体の使い方（何を取得しどう分析するか）は market-scout.md 側を参照すること。**

各項目の構成：①登録先URL ②必要なもの（前提条件）③取得手順 ④認証情報の種類 ⑤費用・無料枠 ⑥注意点

---

## Google系API（③つ共通の下準備）

Google Ads API・Google Search Console API・YouTube Data API v3 の3つは、いずれも**Google Cloud Consoleでのプロジェクト作成**が共通の出発点になる。まずこれを1回行えば、3つのAPIで使い回せる。

### 共通の下準備：Google Cloudプロジェクト作成

1. https://console.cloud.google.com/ にアクセスし、Googleアカウントでログイン
2. 新規プロジェクトを作成（プロジェクト名は任意。例：`marketing-research-org`）
3. 左メニュー「APIとサービス」→「有効なAPIとサービス」から、使いたいAPI（Google Ads API／Search Console API／YouTube Data API v3）をそれぞれ検索して「有効にする」
4. 「認証情報」タブでOAuth 2.0クライアントID（またはAPIキー）を作成
   - OAuth同意画面の設定が必要（アプリ名・サポートメール・スコープ設定）
   - テスト段階は「テストユーザー」に自分のGoogleアカウントを追加すれば動作する
5. `client_id`・`client_secret`を控え、`.env`等の環境変数として管理する（コードに直書きしない）

この共通準備をした上で、各API固有の追加手続きへ進む。

### API①：Google Ads API

**登録先：** https://ads.google.com/aw/apicenter

**必要なもの：**
- Google広告の**クライアントセンター（MCC）アカウント**（通常のGoogle広告アカウントとは別。新規作成する場合はGoogle広告アカウントに未関連付けのメールアドレスが必要）
- 稼働している自社サイトのURL（審査時に確認される。サイトが未公開だと申請が通らない）
- 上記「Google系API共通の下準備」で作成したOAuth 2.0クライアントID

**取得手順：**
1. MCCアカウントを作成（既存のGoogle広告アカウントがあればそこからリンク可能）
2. MCCアカウントで https://ads.google.com/aw/apicenter にログインし「API センター」へ
3. **開発者トークン（Developer Token）**の申請フォームに入力（利用目的・会社情報・サイトURL）
4. 申請後、初期状態では「エクスプローラーアクセスレベル」（テスト用途中心）が付与される。**本番アカウントに対してAPI呼び出しを行うには「基本アクセスレベル」または「標準アクセスレベル」の追加申請と審査が必要**（審査には数日〜数週間かかる場合がある）
5. サービスアカウントを作成し、JSON形式の秘密鍵ファイルを取得（OAuth2.0認証用）
6. 開発者トークン（22桁の英数字）・`client_id`・`client_secret`・`refresh_token`・**顧客ID（10桁、ハイフン除去）**を環境変数に設定

**認証情報：** 開発者トークン＋OAuth2.0（サービスアカウントキーまたはユーザー認証）

**費用：** 無料（広告出稿の有無に関わらず取得可能。ただし広告未出稿アカウントは検索ボリュームが「1万〜10万」等の幅表示になる点に注意）

**注意点：** 4つのAPIの中で**唯一「審査」が必要**で準備に最も時間がかかる。MCCアカウント作成からトークン申請、本番アクセス承認まで余裕を持って進める。

### API③：Google Search Console API

**登録先：** 上記の「Google系API共通の下準備」内で有効化

**必要なもの：**
- 分析対象サイトが**Google Search Consoleに登録・所有権確認済み**であること（未登録の場合は https://search.google.com/search-console で先に登録する）
- OAuth 2.0クライアントID（共通の下準備で取得済みのもの）

**取得手順：**
1. Google Cloud Consoleで「Search Console API」を有効化（共通の下準備の手順3）
2. OAuth同意画面でスコープに `https://www.googleapis.com/auth/webmasters.readonly` を追加
3. 初回実行時にブラウザでOAuth認証フローを通し、`refresh_token`を取得・保存する
4. （推奨）MCPサーバー `mcp-server-gsc` を利用すれば、Claude Code/claude.ai から直接データ取得が可能になる。npm等でセットアップ

**認証情報：** OAuth 2.0（追加の審査・申請は不要）

**費用：** 完全無料

**注意点：** 自社サイトのデータのみ取得可能。3つのGoogle系APIの中で**最も準備が簡単**（審査不要・即日利用可）。

### API④：YouTube Data API v3

**登録先：** 上記の「Google系API共通の下準備」内で有効化

**必要なもの：**
- Google Cloudプロジェクト（共通の下準備で作成済みのもの）
- 公開データの取得のみならAPIキーで十分。コメント投稿等プライベート操作が必要な場合のみOAuth2.0

**取得手順：**
1. Google Cloud Consoleで「YouTube Data API v3」を有効化
2. 「認証情報を作成」→「APIキー」を選択（公開データの検索・動画情報・コメント取得はこれで足りる）
3. APIキーの使用制限を設定（推奨：HTTPリファラーまたはIP制限をかけてキーの不正利用を防ぐ）
4. ライブ配信の同時接続数・スパチャ額（`liveBroadcasts`/`liveChatMessages`）を取得する場合はOAuth2.0が必要になるケースがあるため、共通の下準備のOAuthクライアントIDを使う

**認証情報：** APIキー（基本）／OAuth2.0（一部エンドポイント）

**費用：** 無料（1日10,000クォータ）

**注意点：** 4つのGoogle系の中で**審査不要・即日利用可能**。ただしクォータ消費（`search.list`が100クォータと重い）に注意し、同じ検索を繰り返さない設計にする。

## Google Trends（pytrends）

**登録先：** 不要（非公式ライブラリのため、登録・APIキー取得手続きなし）

**必要なもの：** Python環境

**取得手順：**
```bash
pip install pytrends
```
```python
from pytrends.request import TrendReq
pytrends = TrendReq(hl='ja-JP', tz=540)
```
これだけで利用開始できる。

**認証情報：** 不要

**費用：** 完全無料

**注意点：** Google公式のAPIではなく、Googleトレンドの検索結果ページを解析する非公式ライブラリ。仕様変更やIPブロックのリスクがあるため、リクエスト間隔を60秒以上空ける。長期運用する場合は代替手段（有料の公式データ等）も検討候補として把握しておく。

## X API v2

**登録先：** https://developer.x.com/

**必要なもの：** Xアカウント（電話番号認証済みを推奨）

**取得手順：**
1. developer.x.com にアクセスし、Xアカウントでログイン
2. 「Sign up for Free Account」からデベロッパーアカウント登録（利用目的の説明文が必須。「情報収集・分析目的」であることを具体的に記載する）
3. プロジェクトとアプリを作成（Freeプランはアプリ1件まで）
4. 「Keys and tokens」タブでAPIキー・APIキーシークレット・Bearer Tokenを発行し環境変数に保存
5. **2024年以降、X APIは従量課金（Pay-as-you-go）制に移行済み**。新規デベロッパーコンソールの利用には少額のクレジット購入（$5〜）が求められる場合がある。购入前に無料枠（月間10万リクエストまで無償）の範囲で運用できるか設計を確認する

**認証情報：** APIキー／Bearer Token（OAuth 2.0 App-Only推奨）

**費用：** 無料枠：月間10万リクエストまで無償（2026年時点の従量課金モデル。超過分は段階的単価で課金）。旧来の「Freeプラン＝月100リクエスト」という情報は古いため、**利用開始前に developer.x.com の最新料金ページを必ず確認する**

**注意点：** X APIは値上げ・プラン変更が頻繁に発生している領域。運用開始のたびに最新のプラン内容を確認すること。検索エンドポイント（`/2/tweets/search/recent`）の利用可否はプランに依存する。

## Reddit API

**登録先：** https://www.reddit.com/prefs/apps

**必要なもの：** Redditアカウント

**取得手順：**
1. Redditにログインした状態で https://www.reddit.com/prefs/apps にアクセス
2. ページ下部の「create another app...」からアプリを新規作成
3. アプリタイプは「script」を選択（個人・社内利用のスクリプト用途に適する）
4. 作成後に表示される`client_id`（アプリ名の下に表示される英数字）と`client_secret`を控える
5. Pythonの場合は`praw`ライブラリでの認証にこの2つと自分のRedditアカウント情報（またはApp-onlyのOAuth）を使う

```bash
pip install praw
```

**認証情報：** OAuth 2.0（`client_id`＋`client_secret`＋`user_agent`）

**費用：** 無料（非商業・個人利用の範囲）。商用利用は従量課金（$0.24/千リクエスト）

**注意点：** 利用規約上「非商業目的」の範囲が無料。社内分析が「商業目的」に該当するかは利用規約の解釈次第のため、本格運用前に最新の利用規約を確認する。レート制限は60リクエスト/分（OAuth使用時）。

## 求人ボックス 求人検索API（パブリッシャープログラム）

**登録先：** https://求人ボックス.com/求人検索API （または「求人ボックス パブリッシャープログラム」で検索）

**必要なもの：** 事業者情報・利用目的の説明

**取得手順：**
1. 求人ボックスの求人検索APIパブリッシャープログラムページから申込フォームに入力
2. 利用目的（本用途では「社内でのアカウント分析・ICP調査のための社内利用」である旨）を具体的に記載する
3. **審査を通過する必要がある**（審査基準は非公開。本来は「自社サイトへの求人表示・クリック課金」を前提としたプログラムのため、社内リサーチ用途での承認可否は申込時に個別確認するのが望ましい）
4. 承認後、認証情報（APIキー等）が発行される

**認証情報：** 審査通過後に発行されるパートナー用認証情報

**費用：** 無料

**注意点：** 審査に時間がかかる可能性がある。承認が得られない・遅い場合は`ハローワーク求人情報API`（審査不要）を先に運用しつつ並行申請するのが現実的。取得した求人データを表示以外の用途（社内分析）に使う場合、利用規約上の許諾範囲を必ず確認する。

**費用：** 完全無料

**注意点：** 提供データの対象期間（例：2019〜2021年等）が固定されている場合があるため、**最新年度のデータが提供されているか利用時に確認する**。1kmメッシュ〜市区町村単位の粒度のため、個店商圏レベルの詳細分析には別途モバイル空間統計等の有償データが必要になる場合がある。

## DataForSEO（SEO：検索ボリューム・SERP・被リンク・オンページ診断）

**登録先：** https://app.dataforseo.com

**必要なもの：** メールアドレス・事前入金（プリペイド従量課金）

**登録先：** https://otterly.ai

**必要なもの：** クレジットカード（**Standardプラン以上の契約が必須**）

**取得手順：**
1. otterly.ai にアクセスし、無料トライアル（クレジットカード登録不要）でまず画面を確認する

3. 契約後、管理画面の「API」設定からAPIキーを発行する

標準対応エンジンはChatGPT・Google AI Overviews・Perplexity・Microsoft Copilotの4つで、

## （参考）IP協業向けに追加検討するデータソース

`_shared/skills/fandom-tieup.md`で言及している以下は、本格運用する場合に追加で準備を検討する。

### Spotify API

**登録先：** https://developer.spotify.com/

**必要なもの：** Spotifyアカウント（無料アカウントで可）

**取得手順：**
1. developer.spotify.com にログインし「Create app」からアプリを作成
2. `Client ID`と`Client Secret`が即時発行される
3. Client Credentials Flow（OAuth2.0）でアクセストークンを取得する（ユーザーデータではなくアーティスト情報等の公開データ取得には十分）

**認証情報：** OAuth2.0（Client ID/Secret）

**費用：** 無料

**注意点：** 審査不要で即日利用可能。ただし取得できるデータ範囲（monthly listeners等）はAPI仕様変更が度々あるため、実装前に最新のAPIリファレンスを確認する。

### pixiv

**登録先：** 公式の一般公開APIは提供されていない（非公式クライアント向けの内部APIのみ）

**注意点：** 利用規約上グレーな非公式手段に依存することになるため、**本組織としての正式なデータソース採用は推奨しない**。二次創作の量・質は目視確認（STEP8のサブ工程）で代替するか、pixivが公式に提供する統計情報（ランキングページ等の公開情報の範囲）に留める。

### メルカリ等フリマ相場

**登録先：** 公式の一般公開APIは提供されていない

**注意点：** スクレイピングを行う場合はrobots.txt・利用規約を必ず確認し、`_shared/agents/market-scout.md`の「企業公式サイトへのスクレイピング」の収集ルール（アクセス間隔1〜3秒等）に準拠する。取得停止・法的リスクを避けるため、この用途は優先度を下げ、他の定量データで代替できないか先に検討する。

### チケット販売・イベント情報

**登録先：** サービスごとに異なる（例：チケットぴあ・イープラス等は基本的に一般公開APIなし）

**注意点：** 多くの場合、公式ヒアリング（STEP6）や目視確認（会場キャパシティ・完売速度の公開情報）で代替する。API化は現時点では難しいため、market-scoutの自動収集対象からは除外し、insight-analystの手動リサーチ項目として扱う。

## 準備優先度の目安

初めて環境構築する場合、以下の順で着手すると効率的。

| 優先度 | データソース | 理由 |
|-------|-----------|------|
| **最優先（即日〜数日）** | Google Trends／楽天Ichiba／NewsAPI／ハローワーク求人API／RESAS-API／Reddit API／Search Console API／YouTube Data API | 登録が簡単、または審査不要ですぐ使える |
| **次点（要OAuth設定・数日）** | X API／Spotify API | 開発者ポータルでの申請・料金体系の確認が必要 |
| **時間がかかる（審査あり・数週間見込む）** | Google Ads API／求人ボックスAPI | MCCアカウント作成・開発者トークン審査、または社内利用目的での審査通過が必要 |
| **予算確保のうえ導入（有償・すぐ使える）** | DataForSEO／Otterly.ai（Standard以上） | 審査不要で即日利用可能だが、事前入金・月額契約が必要。SEO/LLMOを本格運用する場合の主軸候補 |
| **状況に応じて（有償検討）** | モバイル空間統計（詳細版） | 無料版で足りない場合のみ、法人契約を検討 |
| **非推奨・代替手段を使う** | pixiv公式API／メルカリ公式API | 一般公開APIが存在しないため目視・規約遵守のスクレイピングで代替 |
