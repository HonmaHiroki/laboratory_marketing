## デザインテイスト（参考サイト準拠）

ドコモ MAX 特典特設サイト（`ssw.web.docomo.ne.jp/max/` 系9ページ）のスクリーンショットと、キャンペーンKV「人生にもっとエンタメを！」をもとに、**黒基調＋レッドCTA＋ゴールドアクセント**へ合わせています。

| 参考サイトの特徴 | 実装 |
|---|---|
| ページ全体が黒基調 | `--bg:#000` を基準に、`#0C0C0C`（セクション交互）／`#181818`（カード）で階層化 |
| 白は密度の高い情報ブロックのみ「島」として使用 | 料金プランカード（`.plan`）とエンタメLPの料金ブロックのみ白パネル。他は黒 |
| レッドのCTA | `--red:#E60027` → `#FF3D6E` のグラデーションピル＋丸チェブロン |
| ゴールドの帯・枠・ハイライト | `--gold:#FFD900`。見出し強調、対象者チェック／ジャンル診断のボックス枠、注意事項、`.verify` マーキングに使用 |
| 中央寄せ見出し＋左右の細い罫線 | `.sec__eyebrow` を flex＋擬似要素の罫線で実装 |
| 赤い丸数字の手続きステップ | `.steps li::before` を赤のグラデーション円に |
| サービスのタブ切替UI | エンタメLPのジャンル診断を6チップのタブ型に。選択中は赤背景 |
| 特典別ページごとに色が変わる | 特典カードの上辺ボーダーをサービス別の色に（DAZN=グリーン／NBA=オレンジ／dアニメ=ダークレッド／Lemino=ピンクレッド） |
| 最下部の赤い固定CTAバー | 追従CTAを黒バー＋赤ピルに |
| KV：ゴールドの劇場ビジュアル | FVをゴールドのグラデーション＋紙吹雪質感（CSS）に。実写KVに差し替え可能な構造 |
| KV：白の袋文字 | 見出しに `-webkit-text-stroke` ＋ `paint-order` で縁取り＋影 |
| KV：プランロゴのロックアップ | 「ドコモ（マゼンタ枠）MAX／ドコモポイ活（ゴールド枠）MAX」をCSSで再現。両LPのFV共通 |
| KV：下部のオファー帯 | 「毎月好きなサービスを追加料金0円で2つ選べる！」＋サービスチップ＋注釈（※1〜3）を帯として実装 |

**色値はスクリーンショットからの目視採寸のため近似値です。** 正確な値が判明した場合は、各HTMLの `:root` にある変数（`--bg` `--red` `--gold` ほか）を差し替えるだけで全体に反映されます。

## 実装済みの仕様｜キャンペーンLP（index.html）

**2026-08-16 全面改訂。** テレマN1分析（成約者52人）のPPTXを受領し、Bランクの定義・提案コンセプトが構成書と異なることが判明したため、セールスレター構成・LP構成ごと作り直しています（旧版はGit履歴を参照）。

### 設計の起点

| テレマ資料の指定 | LPへの実装 |
|---|---|
| Bランク＝「既にサブスク接点があり提案理由は作れるが、決め手がない層」 | FVから「不安解消」ではなく**利用実態の確認**で入る構成に変更 |
| 提案コンセプト「利用実態起点の実質負担最適化」 | LP全体を、使っているサービス → 損失のコスト → 実質負担の計算、という順に再構成 |
| 損失のコスト＝別払いサブスク費＋プラン差額−ポイント還元−特典で代替できる価値 | この式をFVに図解として掲示し、**STEP 3のシミュレーターで実際に計算**する |
| 解決方針「強い軸から入る→補助訴求を1つ足す→最後に実質負担で納得させる」 | STEP 1の選択に応じて、One to Oneオプション（家族／ギガ／手続き）に目印を付ける |
| 課題「エンタメ特典と爆アゲ還元の違いを理解しづらい」 | STEP 4を**3つの仕組みの違い**を明示するセクションとして新設 |
| 転換点「違約金なしで戻せる安心感」 | STEP 7でリスクリバーサルとして独立セクション化 |
| 避けるべき訴求「料金が上がることを隠す」「無料になると誤認させる」 | 「全員が安くなるプランではありません」を明記。FAQ冒頭を「Netflixが無料になるのか」に。計算結果が増額の場合もそのまま表示 |
| クロージング3パターン（下がる／還元込みで実質安い／安くならないが価値） | 最終CTAを**計算結果に応じて3パターン出し分け** |
| N1の実データ（差額330〜1,100円でも成約） | STEP 8「実際の判断例」として3件掲載 |

### セクション構成（13）

FV → STEP 1 エンタメ問診 → STEP 2 見落とし4つ → STEP 3 実質負担シミュレーション → STEP 4 3つの仕組みの違い → STEP 5 One to Oneオプション → STEP 6 プランと割引 → STEP 7 安心材料＋正直な但し書き → STEP 8 実際の判断例 → STEP 9 FAQ → 最終CTA → P.S. → フッター

### 実質負担シミュレーター（中核モジュール）

- 入力：STEP 1で選んだサービス＋いまのスマホ月額＋爆アゲ対象の合計月額＋適用できる割引
- 計算：`(ドコモMAX月額 − 割引) − 現在月額 − 選べる特典で置き換えられる支払い（高い順に最大2つ） − 還元`
- 出力：明細＋実質増減＋判定（下がる／差が小さい／上がる）。判定は最終CTAの文面と追従CTAの表示に連動
- 定数は `MAX_BASE` / `REWARD_RATE` / `PERK_LIMIT` としてJS冒頭に集約。還元率は説明用の仮値

### 計測イベント

`lp_view` / `lp_campaign_fv_cta_click` / `entertainment_survey_start` / `entertainment_survey_select` / `simulator_input` / `simulator_complete`（net・verdict・diff・perk_saving・reward_back を付与）/ `compare_module_view` / `option_module_view` / `faq_open` / `faq_expand_all` / `application_click` / `recalc_click` / `consult_click` / `save_for_later_click` / `sticky_cta_click` / `ps_cta_click`

全イベントに `perks` / `rewards` / `ctx`（STEP 1の選択内容）が付与されるため、**訴求軸別のCVR比較**がそのまま取れます。

### ABテスト（レビュー用切替）

| テスト対象 | パラメータ |
|---|---|
| FVヘッドライン（損失回避／現状維持への問いかけ） | `?fv=a` / `?fv=b` |
| シミュレーターの位置（問題提起の後／問診の直後） | `?sim=a` / `?sim=b` |

WFシート `03_エンタメWF` のBランク行（8セクション）＋原稿シート `03_エンタメLP原稿` のP.S.を実装しています。

| 指定 | 実装状況 |

| 特典カード5枚 | DAZN／NBA／dアニメストア／Lemino／統合（未確定者向け）。原稿シート `07_特典別モジュール原稿` の見出し・本文・CTAをそのまま使用 |

| 計測イベント | `lp_view` / `lp_ent_fv_cta_click` / `genre_diagnosis_start` / `genre_diagnosis_complete` / `perk_card_click_{perk}` / `scene_module_view` / `ent_to_campaign_click` / `perk_notice_open` / `ent_faq_open` / `lp_ent_bottom_cta_click` / `ps_cta_click`。全イベントに `genre` パラメータが付与される |

## 公開前に必ず対応が必要な項目

1. **モックアップ表示の削除**：最上部の帯、右上のABパネル（`.mock-banner` / `.rev` / `.rev-toggle`）、`<meta name="robots" content="noindex, nofollow">`
1-b. **カラー値の確定**：現在の色は参考サイトのスクリーンショットからの目視採寸です。正式なブランドカラー値が入手できたら `:root` の変数を差し替えてください
2. **法務・公式確認**：黄色い網掛け（`.verify`）を付けた数値・条件がすべて対象です（`08_表記確認メモ` に準拠）
   - 3,000ポイントの付与条件・進呈時期・有効期限・対象外条件
   - 対象プランの最新の範囲
   - プラン料金（8,448円／5,148円／11,748円／2,948円）、還元率10%、上限5,000pt、選べる特典の対象サービス数
3. **リンク先の設定**：`href="#"` のCTA・フッターリンクを実URLに差し替え
4. **UTM／計測タグ**：`utm_source={media}&utm_medium=paid&utm_campaign=max_btype&utm_content={creative}_{variant}` をGTM側で設定

## 構成書からの意図的な差分

- **キャンペーンLPは構成書のセクション構成を採用していません。** 構成書のBタイプは「比較検討・不安解消型（PASONA型）」ですが、テレマ分析のBランクは「既に利用接点があり提案理由は作れる層」で、提案コンセプトも「利用実態起点の実質負担最適化」です。定義そのものが異なるため、テレマ分析側を優先して構成を作り直しました。旧構成（対象者チェック／FAQ配置ABテスト等）はGit履歴に残しています。
- 旧版にあった「対象者チェック」は、より強い判断材料になる**実質負担シミュレーター**に置き換えました。これに伴い `eligibility_check_start` / `eligibility_complete` は `entertainment_survey_start` / `simulator_complete` に変わっています。GTM側の設定変更が必要です。
- エンタメLPのFV見出しは、Bランク原稿（`03_エンタメLP原稿`）とABテスト差分（`06_ABテスト差分コピー`）で別の文言が指定されています。**Bランク原稿を既定**とし、ABテスト2案は切替候補として保持しました。
- エンタメLPのP.S.はWFシートの8セクションには含まれていませんが、原稿シートに存在するため、制作メモ「注意事項導線を近くに配置」に従いクロージング直後に配置しています。
- **配色は構成書 `instruction.md §4` と不一致です。** 構成書はメイン `#1F4E78`・サブ `#EAF3F8`・白基調を指定していますが、参考サイト（ドコモ MAX 特典特設サイト）に合わせるという後続の指示を優先し、黒基調＋レッド＋ゴールドに変更しました。構成書側 §4 の記述も更新するかどうかは別途判断が必要です。なお CTA の `#D9002F` は参考サイトのレッド `#E60027` にごく近いため、実質的に維持されています。
